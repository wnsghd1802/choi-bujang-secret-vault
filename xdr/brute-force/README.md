# XDR-01 무차별 로그인 탐지

## 실행

```sh
npm run xdr:run -- brute-force
node xdr/brute-force/replay.mjs
node --test test/brute-force.test.mjs test/xdr-run.test.mjs
```

첫 명령은 공식 실행기로 `result.json`을 만듭니다. 두 번째 명령은 시험 경보 시각 순서로 차단 연결을 재생하고 `xdr/alerts.log`에 block/alert만 한 줄씩 추가합니다. 반복 실행하면 로그가 추가로 쌓입니다. `replay-report.json`은 최신 실행만 기록합니다.

공식 가상 경보 28건: block 10, alert 9, record 9. 읽은 줄 28건, 정상 이벤트 9건 중 차단 0건입니다. 이 기대값은 경보 내용을 직접 검토한 로컬 확인이며 비공개 심판 정답이 아닙니다. 실제 경보를 보내거나 실제 접속을 막는 실행이 아닙니다.

## 동작과 근거

- `read-alerts.mjs`: 시각·출발 주소·계정·규칙 수준·설명만 추출합니다. 일반 계정 이름은 지문으로 바꾸고, 설명의 비밀번호/토큰 등 알려진 형태를 가립니다. 원본 경보는 수정하지 않습니다. 추출 내용 전체를 운영 로그로 출력하지 마세요.
- `patterns.json`: [MITRE ATT&CK T1110](https://attack.mitre.org/techniques/T1110/)의 반복 추측·여러 계정 대입 형태를 근거로 합니다. 실패 30건, 계정 8개 등의 숫자는 이 실습의 선택이며 MITRE의 표준 임계값이 아닙니다.
- `decide.mjs`: 고수준 T1110 집계 경보와 설명·횟수를 함께 확인합니다. 명시된 시간이 5분을 넘으면 자동 차단하지 않습니다. 시간이 없는 고수준 집계 경보는 Wazuh의 집계를 근거로 삼습니다. 낱개 실패는 동일 주소·계정별 5분 창에서 중복 ID를 빼고 셉니다. 집계 경보를 합산하여 이중 계산하지 않습니다.
- Jev는 설정이 없으므로 기본 실행에서는 호출하지 않습니다. `createDecider({jev})`에 서버 콜백을 연결할 수 있으며 애매한 경보에만 숫자·참거짓 특징을 보냅니다. 주소·계정·원문·비밀번호를 보내지 않습니다. 확신도 0.85 이상은 block, 0.5 이상은 alert, 나머지는 record입니다. 미연결·오류·시간 초과·비정상 응답은 alert로 남습니다. Jev 연결 성공을 주장하지 않습니다.
- `enforce.mjs`: block만 15분 만료되는 주소 거부 규칙으로 만듭니다. 근거 경보는 `event-`와 ID 지문으로 연결합니다. 과거 경보 재생으로 만료 시각이 현재까지 연장되지 않습니다. 저장소는 메모리이며 프로세스 재시작 시 사라집니다.

## 기존 ZTNA와의 연결 한계

현재 `src/decider.mjs`는 모든 요청을 거부하는 시작 틀입니다. 5단계 자료실의 로그인·메모 API와는 별개입니다. `docs/DECIDER_REQUEST.md`의 요청 계약에는 출발 IP가 없으며 허용 reasonCode 등록부도 이 저장소에 없습니다.

따라서 기존 판정기나 요청 형식을 임의로 바꾸지 않았습니다. `withXdrGuard(baseDecide, {store, resolveVerifiedSourceIp, denyResponse})` 연결 부품을 제공하고 가상 정책과 결합해 검증했습니다. 실제 연결에는 운영 엔진이 확인한 출발 IP 공급자와 운영 등록부에 맞는 거부 응답 생성자가 필요합니다. 브라우저 본문/임의 전달 헤더를 신뢰하는 주소 공급자를 만들면 안 됩니다.

유효한 차단 주소는 거부하고 나머지는 기존 판정기로 그대로 넘깁니다. 기존 거부를 허용으로 바꾸지 않습니다. `deny-rules.json`은 시험 경보로 만든 과거 규칙의 기록일 뿐 운영 정책 파일이 아닙니다. 운영 연결·영속 저장·실제 차단은 아직 미구현입니다.
